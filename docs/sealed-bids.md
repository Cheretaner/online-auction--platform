# Sealed Bids

## Commitment Format
The commitment format uses the SHA-256 algorithm to hash the bid details. The resulting hash is encoded as a lowercase hex string.

## Format
`SHA-256(auctionId + "|" + amount + "|" + nonce)`

- `nonce`: A random 32-byte hex string generated by the client.

## Lifecycle
1. **Submit sealed**: Bidders submit their bids containing a commitment hash.
2. **Auction closes**: The auction period ends and no further bids are accepted.
3. **Officer opens sealed bids**: An organization officer triggers the opening of the sealed bids.
4. **Amounts revealed**: The true bid amounts are revealed and evaluated.

## API Contract
- **Request**: The bid request body must include the `commitmentHash` field.
- **Storage**: The server stores the `commitmentHash` alongside the bid record.
- **Verification**: When the sealed bids are opened, the commitments are verified by checking that the hash matches the provided amount and nonce.

## Client Implementation Note
Use the WebCrypto API in the browser to generate the commitment:

```javascript
const nonce = crypto.getRandomValues(new Uint8Array(32));
const nonceHex = [...nonce].map(b => b.toString(16).padStart(2, '0')).join('');
const message = `${auctionId}|${amount}|${nonceHex}`;
const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(message));
const commitmentHash = [...new Uint8Array(hash)].map(b => b.toString(16).padStart(2, '0')).join('');
```

**Important**: The client must save the nonce locally — it's needed to prove the bid during opening.
